# 本地数据标注管道

主界面显示未完成队列与已完成归档。类别选择直接映射 `<任务>/<类型>/<题目>/` 目录，轮次选择映射其输入子目录；分类及数量均从队列读取，不保存索引。每个完整物品格只有“是／否”；已有 AI 建议初始置为是。确认或暂跳过后进入当前类别下一项，该类别完成后提示选择其它类别；失败时保留当前项。暂跳过不会移走数据，切换类别或轮次会保留本页内存中的未确认编辑。

网页按当前任务、题目展示 `图标参考/` 中的参考图片、名称及来源，并展示 AI 建议说明。参考图是审核辅助资料；AI 建议须经用户确认，不自动转为正式答案。参考图固定随软件维护，不提供编辑管理界面。

寻物失败及未确认拼图保存原图后，调用 `annotation_queue.enqueue(source, task, kind, topic, name)` 入队，由 AGENT 先完成 AI 标注，再提交人类确认；确认后继续归档、固化测试和迭代识别。寻物失败时，Lua 在持久化重试预算内先通过免费重试绕过，等待人类完成标注，未确认建议不能作为生产真值。流程页面、按钮与状态变化由 AGENT 自主核对原图和业务状态并直接固化，不进入待标注队列；入队入口仅接收寻物、找鬼和拼图答案，不接收流程页面。当前支持 900×1600 寻物物品格，以及师门、抓鬼的四格拼图。

## 拼图标注

选择拼图类别后，页面显示还原工作区和采集原图。原图四块按左上、右上、左下、右下标为 A、B、C、D；拖动到另一格会交换两块，移出拼图后松开会取消。图块只换位置，不旋转或镜像；可隐藏编号查看拼接边缘，也可撤销或恢复本张原图顺序。键盘用空格选择图块、方向键移到另一格、空格交换，Esc 取消。

每张原图独立还原，核对后勾选“本张已还原”；继续拖动会取消该张的勾选。全部原图勾选后，才能点击共用的“确认并下一项”。未确认的排列与勾选只保留于当前页面内存，切换类别、轮次或原图会保留，刷新网页后丢失。AI 建议可作为初始排列，但不会自动勾选。已完成归档展示确认排列与原图，只读。

四格裁切使用任务的 `testdata/<任务>/拼图/格位.json`，不运行拼图识别器猜答案。答案沿用 `预期`：抓鬼每张原图保存 `puzzle_order`，师门保存 `puzzle_locations`；均按恢复图的左上、右上、左下、右下记录所用原图块，分别为 A～D 或 1～4。只保存一份答案，原图与审核依据随整项归档。`freeze-annotations.py` 共用固化入口处理寻物、找鬼和拼图；拼图按题型保留每张原图的确认排列。

拼图也可在会话中明确确认对应原图及排列，无须重复网页确认。AGENT 可使用 `annotation_queue.confirm(identity, document, evidence=用户明确确认的消息或审核依据)` 归档，再固化；审核记录保存会话依据，不声称用户点击了网页。AI 建议本身不能视作用户确认。

```powershell
python annotation-web/server.py
python annotation-web/suggest.py
python annotation-web/check_rounds.py
```

服务只监听本机，打开 http://127.0.0.1:8765 。`--port` 可指定端口。`suggest.py` 使用生产识别代码及可用 GPU 为未完成的酒类输入生成建议；其它门类暂无自动建议时在页面明确提示。`check_rounds.py` 检查本地队列中酒类输入的拼接与原图映射，不计入正式识别评分。

## 采集完整性反馈

采集完整性只按图片高度判断。寻物、找鬼使用现有拼接器去重后的物品长图，不计顶部题干：高度达到2760像素为完整，低于阈值提示实际高度与所需高度。拼图逐张检查原图高度，全部达到1600像素为完整。不能读取或拼接图片时显示具体失败原因；不检查滚动条、题干一致性、页面连续性或触底位置。

2760像素阈值沿用用户确认完整的师门酒 `20261012_131613_第09轮`：20行，每行138像素。重复截图不增加去重长图高度。类别里的“9项”表示输入轮次数量。

入队及打开图片共用同一高度校验。打开图片时自动重算旧规则或“待打开检查”的反馈，不留下“未核验”状态。结果写入 `采集反馈.json`，随确认归档保留；已有答案不改动。反馈绑定原图文件及 SHA-256，增删页或像素变化后重新校验，原图与长图缓存同时失效。完整性通过不代替人类确认识别答案，未标区域保持未知。

```powershell
python annotation-web/check_capture.py --stage pending
python annotation-web/check_capture.py --stage confirmed --id '师门/寻物/鞋子/20261013_151534_第001轮'
```

检查返回结构化反馈；不完整或核验失败时退出码为1，让后续归档 AI 收到失败反馈。`--record` 将额外依据写在原图旁；`--unrecoverable --evidence '明确反馈依据'` 记录无法补采。已确认答案不因负反馈被删除或重复询问。

## 文件交接

`未完成/` 与 `已完成/` 各保留 `.gitkeep` 以将目录纳入 Git；目录内其余内容均忽略，不提交。其它网页源码和工具照常管理。

- 需人类确认的识别题由采集工具送入 `annotation-web/未完成/<任务>/<类型>/<题目>/<输入>/`，保存脱敏原图、简短来源及 AI 标注；提交人类确认前由 AGENT 补齐标注及不确定项说明。流程截图留在 `debug-runs/` 并由 AGENT 直接固化。网站不扫描历史采集或正式测试目录重新入队。
- 点击“确认并下一项”将整项移入 `annotation-web/已完成/`，写入一份 `答案.json` 和审核依据。寻物答案使用现有的 `正确`、`反例` 格式，位置以原图为准；拼图使用 `预期` 格式。未完成编辑仅保留于当前页面内存。
- 已完成列表直接从队列文件发现，不建数据库、状态索引或消费登记。外部删除 `答案.json` 或整项目录后，页面自动移除该项；缓存不得使其复活。网站不删除数据、不写正式真值。
- AI 从已完成归档读取原图、答案和审核依据，另行固化到 `testdata/` 并验证。核对正式用例中的全部原图及已确认答案后，调用共用 `annotation_queue.remove_frozen(identity, target)` 删除对应标注归档，保留唯一正式用例；固化工具自动完成此步骤。来源、审核依据及采集反馈先保留到正式用例，不需调用网站接口。原始采集证据仍在 `debug-runs/`。

未完成默认按题目及采集次序排列，酒类优先。已完成归档只读，可点击查看。长图顶部保留第一张原图的题目及要求数量，下面只绘制完整物品行；滚动回弹补拍的行补入相应位置，重复行只显示一次。绘制与点击共用逐行原图映射。

网页与队列文件管道的共享代码在 `scripts/perception/lib/annotation_queue.py`；需要人类确认的识别题采集完成后调用入队入口。`server.py` 提供共用文件读取及确认接口，`app.js` 负责类别、轮次、撤销、编辑保留和归档交互，`puzzle.js` 负责图块裁切、拖动与逐张核对。参考资料与 AI 建议说明共用现有区域。工具测试随工具维护，并纳入 `scripts/test.py`；报告和长图输出到 `debug-runs/`。
