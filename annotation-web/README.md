# 本地数据标注管道

主界面显示未完成队列与已完成归档。类别选择直接映射 `<任务>/<类型>/<题目>/` 目录，轮次选择映射其输入子目录；分类及数量均从队列读取，不保存索引。每个完整物品格只有“是／否”；已有 AI 建议初始置为是。确认或暂跳过后进入当前类别下一项，该类别完成后提示选择其它类别；失败时保留当前项。暂跳过不会移走数据，切换类别或轮次会保留本页内存中的未确认编辑。

网页按当前任务、题目展示 `图标参考/` 中的参考图片、名称及来源，并展示 AI 建议说明。参考图是审核辅助资料；原始 AI 建议不自动转为正式答案。参考图固定随软件维护，不提供编辑管理界面。

运行期拼图类失败沿用本页的标注、还原与独立自查流程，后续固化、校准、回归、Lua 受控复测及方案检验上限见 [离线识别与用例维护](</D:/Agent Repo/my_pocket_automation/scripts/perception/README.md>)；其他运行期失败默认不修改源码、参数或特征，按 [设备运行期恢复](</D:/Agent Repo/my_pocket_automation/scripts/device/README.md>) 处理，外部恢复限额和人工介入条件以该规则为准。

明确开展识别开发或用例维护时，寻物、找鬼及拼图经完整性核验后，调用 `annotation_queue.enqueue(source, task, kind, topic, name)` 入队，由 AGENT 完成标注、独立自查并记录依据，再按用户授权归档；未经自查的建议不能作为生产真值。在该开发工作中，流程页面、按钮与状态变化由 AGENT 自主核对原图和业务状态并直接固化，不进入待标注队列；入队入口仅接收寻物、找鬼和拼图答案，不接收流程页面。当前支持 900×1600 寻物物品格，以及师门、抓鬼的四格拼图。

## 拼图标注

选择拼图类别后，页面显示还原工作区和采集原图。原图四块按左上、右上、左下、右下标为 A、B、C、D；拖动到另一格会交换两块，移出拼图后松开会取消。图块只换位置，不旋转或镜像；可隐藏编号查看拼接边缘，也可撤销或恢复本张原图顺序。键盘用空格选择图块、方向键移到另一格、空格交换，Esc 取消。

AGENT 须实际操作标注器，逐张独立还原并目视自查图块拼接连续性，不能把算法建议当作已核验答案。核对后勾选“本张已还原”；继续拖动会取消该张的勾选。全部原图勾选后，才能点击共用的“确认并下一项”。未确认的排列与勾选只保留于当前页面内存，切换类别、轮次或原图会保留，刷新网页后丢失。AI 建议可作为初始排列，但不会自动勾选。已完成归档展示确认排列与原图，只读。

四格裁切使用任务的 `testdata/<任务>/拼图/格位.json`，不运行拼图识别器猜答案。答案沿用 `预期`：抓鬼每张原图保存 `puzzle_order`，师门保存 `puzzle_locations`；均按恢复图的左上、右上、左下、右下记录所用原图块，分别为 A～D 或 1～4。只保存一份答案，原图与审核依据随整项归档。`freeze-annotations.py` 共用固化入口处理寻物、找鬼和拼图；拼图按题型保留每张原图的确认排列。

用户已在会话中明确确认对应原图及排列时，无须重复网页确认，可用 `annotation_queue.confirm(identity, document, reviewer="human", evidence=用户明确确认的消息)` 归档。AGENT 依授权完成实际还原与独立自查后，使用 `reviewer="agent"` 并提供 `evidence=授权和独立自查依据`；算法建议和 AGENT 自查不得记作人类确认。确认只保存答案，不生成 `审核.md`；原图、还原图及审核依据留在 `debug-runs/`。

```powershell
python annotation-web/server.py
python annotation-web/suggest.py
python annotation-web/check_rounds.py
```

服务只监听本机，打开 http://127.0.0.1:8765 。`--port` 可指定端口。`suggest.py` 使用生产识别代码及可用 GPU 为未完成的酒类输入生成建议；其它门类暂无自动建议时在页面明确提示。`check_rounds.py` 检查本地队列中酒类输入的拼接与原图映射，不计入正式识别评分。

## 采集完整性与高度检查

入队及固化前，AGENT 必须目视核对原图与拼接图的首尾、接缝和缺行，确认来自同一题、同一次采集；不得跨题或跨重试拼接素材。缺页、起点未知、重复末屏或裁切输入不能作为完整用例。缺页须按 [Lua 补采入口](</D:/Agent Repo/my_pocket_automation/scripts/perception/README.md>) 补采；无法补采时不保留正式识物标注归档，不得用 `--allow-partial` 绕过。

高度与页数只是辅助检查，7页或高度达标不能单独证明完整。寻物、找鬼使用现有拼接器去重后的物品长图，不计顶部题干：高度须达到2760像素。拼图取全部原图的最小高度，与1600像素比较。网页用统一模板显示实际高度、阈值及是否达标；不能读取或拼接图片时沿用图片加载错误。

2760像素阈值沿用用户确认完整的师门酒 `20261012_131613_第09轮`：20行，每行138像素。重复截图不增加去重长图高度。类别里的“9项”表示输入轮次数量。

打开图片时直接使用当前图像尺寸，高度检查只存在于内存，不读写采集反馈 JSON，不保存反馈历史。原图变化后，图片及长图缓存失效。高度达标不代替识别答案的独立审核，未标区域保持未知。

```powershell
python annotation-web/check_capture.py --stage pending
python annotation-web/check_capture.py --stage confirmed --id '师门/寻物/鞋子/20261013_151534_第001轮'
```

命令只在标准输出显示当前高度、阈值与是否达标，不生成文件；高度不足或图片无法读取时退出码为1。命令不代替上述完整性核验与补采处理。

## 文件交接

`未完成/` 与 `已完成/` 各保留 `.gitkeep` 以将目录纳入 Git；目录内其余内容均忽略，不提交。其它网页源码和工具照常管理。

- 需人类确认的识别题由采集工具送入 `annotation-web/未完成/<任务>/<类型>/<题目>/<输入>/`，保存脱敏原图、简短来源及 AI 标注；提交人类确认前由 AGENT 补齐标注及不确定项说明。明确开展流程开发时，流程截图留在 `debug-runs/` 并由 AGENT 直接固化。网站不扫描历史采集或正式测试目录重新入队。
- 点击“确认并下一项”将整项移入 `annotation-web/已完成/`，写入一份 `答案.json`，不生成审核过程文件。寻物答案使用现有的 `正确`、`反例` 格式，位置以原图为准；拼图使用 `预期` 格式。未完成编辑仅保留于当前页面内存。
- 已完成列表直接从队列文件发现，不建数据库、状态索引或消费登记。外部删除 `答案.json` 或整项目录后，页面自动移除该项；缓存不得使其复活。网站不删除数据、不写正式真值。
- AI 从已完成归档读取原图和答案，另行固化到 `testdata/` 并验证。核对正式用例中的全部原图及已确认答案后，调用共用 `annotation_queue.remove_frozen(identity, target)` 删除对应标注归档，保留唯一正式用例；固化工具自动完成此步骤。正式目录只写原图和答案，来源及建议不复制过去；更正过程留在 `debug-runs/`。

未完成默认按题目及采集次序排列，酒类优先。已完成归档只读，可点击查看。长图顶部保留第一张原图的题目及要求数量，下面只绘制完整物品行；滚动回弹补拍的行补入相应位置，重复行只显示一次。绘制与点击共用逐行原图映射。

网页与队列文件管道的共享代码在 `scripts/perception/lib/annotation_queue.py`；需要人类确认的识别题采集完成后调用入队入口。`server.py` 提供共用文件读取及确认接口，`app.js` 负责类别、轮次、撤销、编辑保留和归档交互，`puzzle.js` 负责图块裁切、拖动与逐张核对。参考资料与 AI 建议说明共用现有区域。工具测试随工具维护，并纳入 `scripts/test.py`；报告和长图输出到 `debug-runs/`。
