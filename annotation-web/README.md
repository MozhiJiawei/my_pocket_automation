# 本地数据标注管道

主界面显示未完成队列与已完成归档。每个完整物品格只有“是／否”；已有 AI 建议初始置为是。确认成功后自动下一项，失败时保留当前项。暂跳过不会移走数据。

启动采集或发现识别错误时，先打开标注器。完整新输入及失败现场由采集工具调用 `annotation_queue.enqueue(source, task, kind, topic, name)` 入队，用户确认后再固化测试和迭代识别。当前支持 900×1600 寻物物品格；拼图及无可识别物品格的画面只展示原图，保留在未完成队列并禁止确认。

```powershell
python annotation-web/server.py
python annotation-web/suggest.py
python annotation-web/check_rounds.py
```

服务只监听本机，打开 http://127.0.0.1:8765 。`--port` 可指定端口。`suggest.py` 使用生产识别代码及可用 GPU 为未完成的酒类输入生成建议；其它门类暂无自动建议时在页面明确提示。`check_rounds.py` 检查本地队列中酒类输入的拼接与原图映射，不计入正式识别评分。

## 文件交接

`未完成/` 与 `已完成/` 各保留 `.gitkeep` 以将目录纳入 Git；目录内其余内容均忽略，不提交。其它网页源码和工具照常管理。

- 完整采集由采集工具主动送入 `annotation-web/未完成/<任务>/<类型>/<题目>/<输入>/`，保存脱敏原图、简短来源及可选建议。网站不扫描历史采集或正式测试目录重新入队。
- 点击“确认并下一项”将整项移入 `annotation-web/已完成/`，写入一份 `答案.json` 和审核依据。答案使用现有的 `正确`、`反例` 格式，位置以原图为准；未完成编辑仅保留于当前页面内存。
- 已完成列表直接从队列文件发现，不建数据库、状态索引或消费登记。外部删除 `答案.json` 或整项目录后，页面自动移除该项；缓存不得使其复活。网站不删除数据、不写正式真值。
- AI 从已完成归档读取原图、答案和审核依据，另行固化到 `testdata/` 并验证。消费完成后可独立删除已完成归档，不需调用网站接口。原始采集证据仍在 `debug-runs/`。

未完成默认按题目及采集次序排列，酒类优先。已完成归档只读，可点击查看。长图顶部保留第一张原图的题目及要求数量，下面只绘制完整物品行；滚动回弹补拍的行补入相应位置，重复行只显示一次。绘制与点击共用逐行原图映射。

网页与队列文件管道的共享代码在 `scripts/perception/lib/annotation_queue.py`；采集完成即调用入队入口。`server.py` 提供文件读取及确认接口，`app.js` 负责队列交互。工具测试随工具维护，并纳入 `scripts/test.py`；报告和长图输出到 `debug-runs/`。
