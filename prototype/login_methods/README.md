# 六种登录入口定位实验

这是能力验证原型，不依赖旧业务脚本。共同目标是：在已有角色的登录首页定位右下角“口袋”，点击后识别游戏的“是否要进入口袋版？”确认页。实验不输入账号密码、不切换或删除角色、不点击确认进入游戏。

五种方案已实际打开确认页；控件定位已实际查询控件树，但没有独立按钮节点。这说明当前入口可以通过像素或文字定位，不能据此声称完整账号登录已经实现。设备为 MuMu，实际横屏截图为 1600×900，应用版本画面显示 2.6.2(3.0.633.0)。

## 六种方案如何工作

| 方案 | 实现与原理 | 本次设备结果 | 能力边界 |
| --- | --- | --- | --- |
| 固定坐标 | Lua 直接点击 `(1534,716)`，不搜索画面 | 打开确认页 | 它只知道位置，不知道那里是否还有按钮；原型先检查入口页且拒绝其他分辨率 |
| 相对坐标／边缘偏移 | Lua 使用 `x=round(1534/1600*W)`、`y=round(716/900*H)`；另记录右侧 66、底部 184 像素偏移算出的坐标 | 比例坐标打开确认页；边缘偏移做了截图实验，未单独点击实测 | 比例坐标假设布局同比例缩放；固定边距假设按钮贴边。两种假设都不是游戏的保证 |
| 多点找色 | 用一个基准颜色加 11 个相对偏移颜色，在右下区域扫描；找到基准点后加偏移得到点击点 | 打开确认页 | 平移不改变点之间距离；缩放会改变距离。纯白颜色点还会受灰化、遮罩和字体变化影响 |
| 图片模板匹配 | Lua `findImageInRegionFuzzy`，把文字区域二值化后找图，返回模板左上角，再加偏移点击图标 | 打开确认页 | 二值化减少彩色背景影响，但模板仍只有一个尺寸；变小、变大、旋转都可能失效 |
| 控件定位 | 电脑端 ADB `uiautomator dump`，按文字／描述找“口袋”，由节点 bounds 求中心 | 4 个容器节点，0 个目标；未点击 | 当前画面是游戏绘制层，按钮没有独立控件节点。仅查询控件树不能恢复游戏内部按钮语义 |
| OCR | 电脑端 RapidOCR + ONNX CPU 找文字框；候选局部放大重识别，漏检时用重叠分块扫描，必须得到“口袋”才接受 | 点击文字打开确认页；最新三轮均通过 | 曾误读为“白袋”或漏检。分块改善部分缩小样本，但仍有真实帧和低亮度样本漏检；置信度不是成功保证 |

前四种定位和点击在设备端触动 Lua 执行；后两种由电脑查询／识别，再用 ADB 点击。OCR 不是触动设备端的独立运行能力，也没有接入云视觉模型。恢复页面和结果核验使用公共的电脑端 OCR／模板机制，不记为被测定位方案的能力。

接口依据：[多点找色](https://helpdoc.touchsprite.com/dev_docs/17/18.html)、[找图及 kind 参数](https://helpdoc.touchsprite.com/dev_docs/18/5.html)、[RapidOCR](https://github.com/RapidAI/RapidOCR)。本次模板用 `degree=90, kind=1, value=180`，不是 OpenCV 的相关系数阈值；两者不能混用。

## 已测到的边界

除了设备点击，还对真实截图进行了电脑端变形实验：平移 `(-160,-100)`、整体缩放至 80%／120%、像素亮度乘 0.6、擦除目标。没有改变设备分辨率，也没有在变形图上操作设备。

| 截图实验 | 固定坐标 | 比例坐标 | 固定边距 | 多点颜色模型 | OpenCV 单尺寸模板 | 本地 OCR |
| --- | --- | --- | --- | --- | --- | --- |
| 真实后续帧 | 命中 | 命中 | 命中 | 命中 | 命中 | 找不到 |
| 平移 | 点偏 | 点偏 | 点偏 | 命中 | 命中 | 命中 |
| 缩小至 80% | 点偏 | 命中 | 落在按钮内 | 找不到 | 找不到 | 命中 |
| 放大至 120% | 点偏 | 命中 | 落在按钮内 | 找不到 | 找不到 | 命中 |
| 亮度降至 60% | 命中位置 | 命中位置 | 命中位置 | 找不到 | 命中 | 找不到 |
| 擦除按钮 | 仍给出坐标 | 仍给出坐标 | 仍给出坐标 | 无候选 | 无候选 | 无候选 |

“命中”按已知按钮区域判定；固定边距在缩放样本中仍落在较大的按钮内，不代表其坐标计算精确。擦除目标时，坐标方法仍给出位置，证明它们需要额外页面门禁；实际设备实验有门禁，不会直接对任意画面盲点。

上表对应 `20261009_193854`，输入为曾发生 OCR 漏检的真实帧 `20261009_193612`。较早的 `20261009_193207` 使用另一真实帧和分块扫描前的 OCR，实现与样本均不同，不用于严格量化算法提升。最新三次设备成功与这个困难帧仍漏检并不矛盾，恰好说明少量成功不能证明稳定。

颜色模型是 Python 的逐通道容差模拟，模板是 OpenCV 相关匹配；这些结果解释原理，不能替代触动原生 API 在其他分辨率上的设备测试。低亮度实验修改截图像素，不等同于 Android 屏幕亮度设置。所有实验都是少量样本，不是可靠性统计。

## 反馈闭环

`观察日志和截图 → 形成假设 → 修改一个特征或参数 → 发布并校验 → 定位 → 点击 → 检查新页面 → 保存结论 → 再复测`

本次实际迭代如下：

1. 冷启动出现较长黑屏，原先固定等待过短。改为带截图的就绪轮询，优先复用首页和取消确认页，再考虑重启。
2. 仅检测右下入口会把“确认页覆盖首页”也当作首页。增加中央确认文字模板门禁，确保每次从无弹窗的首页开始，排除先前确认页造成的假成功。
3. 首版颜色点包括背景，夜间动画导致找不到。用三个真实帧筛选 12 个稳定白色文字像素后重新实测成功。
4. RGB 模板找不到，改为二值化文字模板后重新实测成功。
5. OCR 首次读成“白袋”，加入有边距的局部放大重识别；不把“白袋”直接当作“口袋”。重新实测成功，但复测仍有漏检，再加入重叠分块放大扫描。最新三轮设备均成功；保留困难截图仍漏检的边界证据。

每个设备实验有独立运行编号、配置、校准特征、Lua 源码快照、日志、截图和 `result.json`。每套实验的首轮目录另有 `suite-summary.json`。截图和日志位于 `D:/Agent Repo/my_pocket_automation/debug-runs/<运行编号>/`，默认不提交。

原生日志记录找到的位置、定位 CPU 时间、是否发送点击和正常结束。电脑日志记录页面恢复、发布请求、OCR 置信度、后置页面验证、整轮耗时。`os.clock()` 的设备 CPU 时间、电脑端墙钟时间和整轮耗时是不同指标，不能直接横向排名。模板搜索本次约需 1 秒设备 CPU 时间，不能假设所有找图都很快。

实际通过标准是：已就绪首页 → 被测方案独立定位并点击 → 出现确认文字模板且 OCR 读到口袋／进入等语义 → 脚本回到 `f00`。只发出点击不算成功；找不到目标不改用另一方案兜底。实验停止在游戏确认页，下一轮通过识别“取消”恢复首页。原型不产生信息弹框或 toast；游戏本身的确认页是被测业务界面。

## 运行与复测

电脑 Python 依赖见 `requirements.txt`。本机已有 OpenCV、RapidOCR 3.9.2、ONNX Runtime 和模型文件；首次在新电脑初始化时可能需要下载 OCR 模型。截图识别在本地执行。

```powershell
# 全部六种，每轮从同一首页开始
python 'D:/Agent Repo/my_pocket_automation/prototype/login_methods/experiment.py' --method all

# 单独复测找色，连续三轮
python 'D:/Agent Repo/my_pocket_automation/prototype/login_methods/experiment.py' --method multicolor --repeats 3

# 只做截图边界实验，不操作设备
python 'D:/Agent Repo/my_pocket_automation/prototype/login_methods/boundary.py' --input 'D:/Agent Repo/my_pocket_automation/debug-runs/20261009_192912/res/hello_world_20261009_192912_reset_before.png'
```

多设备时必须显式传 `--device`；ADB 位置不同时传 `--adb <绝对路径>`。同一设备实验必须串行执行，禁止同时启动多个实验进程。需要重新校准时，`--calibrate` 可传多个 1600×900 的首页截图；当前按钮区域是人工确认过的固定校准区域，其他布局需要重新选择区域，不能盲用现有配置。

运行器从仓库外读取 Access Key，动态获取 auth，并将其传入 CLI 子进程环境。通过 `ts-cli.ps1 run -SourcePath <本原型/main.lua>` 发布源码，资源单独 ADB 发布并校验 SHA256。Windows 优先使用 `pwsh`，避免继承环境导致旧版 Windows PowerShell 无法加载 `Get-FileHash`。它不会修改默认 Hello World 原型。

设备端配置和模板分别为 `/storage/emulated/0/TouchSprite/res/login_probe_config.lua`、`/storage/emulated/0/TouchSprite/res/login_probe_pocket_label.png`。资源来源是仓库校准数据和公共按钮截图。运行器只保存脱敏控件树，不把原始控件树、Access Key、auth 或设备身份标识写入仓库。

## 当前阶段的选择

在已验证的同一分辨率、同一入口页上，多点找色可以作为轻量定位候选；二值化模板适合做外观确认；OCR 适合做语义核验和处理难定位文字。固定／相对坐标应放在已确认的页面状态后。控件定位需先证实目标有独立节点。

下一阶段应将“首页、进入确认页、加载中、游戏主页、异常页”做成有界状态机，每次操作验证后置状态，补上目标不存在、遮挡、加载超时、重新登录等样本。当前原型还不能证明账号输入、完整登录、多分辨率、多设备或长期稳定运行的能力。
