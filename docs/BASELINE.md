# 每日自动化基线

## 需求与本轮范围

最终每日目标：师门、抓鬼、乌鸡国、车迟国、开启全部葫芦、签到、领取已达成的活跃度奖励。

代码组织为四类任务：师门、抓鬼、副本、葫芦与活跃度处理。主循环与两个副本已实现；抓鬼已实测野鬼、马面、僵尸、蛇胆酒、骷髅怪寻物及战斗，其他酒类、拼图和完整日循环待验收；师门与收尾处理留空。调测禁止领取副本葫芦或开葫芦，副本通关与奖励处理分开记录，不能据此宣称整日完成。抓鬼完成本身扣精力，默认零预算时主循环会在抓鬼接取前停止。最新实测次数和费用见 `ZHUAGUI_TEST_REPORT.md`。

账号认证人工完成；代码只选择游戏已保存角色并核对身份。没有 session 或账号密码登录模块。

## 调度与恢复

主循环顺序是核对角色 → 师门 → 抓鬼 → 副本内部乌鸡国、车迟斗法 → 收尾处理 → 回主页 → 下一个已配置角色。尚未实现的任务不会伪装成功；阻塞、失败或暂停会停止本轮并保留现场。

任务当前提供 `run(context)`，返回 `status、reason`，副本聚合结果附带 `items`。状态包括 `running、done、blocked、failed、paused、not_implemented`。成功退出脚本和完成业务是两个独立结果。

副本进度按业务日期、固定角色别名、副本 ID 隔离。点击“开启”之前写入 `running`；已有记录不再次开启。恢复先观察现场；已完成记录跳过，运行中记录只接管已有战斗。无所属记录的活动副本不会自动接管。

角色配置、身份特征与授权在仓库外；进度在设备端。当前业务日期取电脑本地日期，游戏刷新时刻与跨日恢复尚未验证；验证之前不用于无人值守跨日运行。设备记录不能任意删除或把别名重新绑定其他角色。

## 验收与下一步

本轮验收是两个副本各五关已完成、精力不减少、奖励未领取，以及主循环身份核对和完成项跳过。详细证据见 [实测报告](DUNGEON_TEST_REPORT.md)。

后续分别实现师门、抓鬼、收尾处理，再验证单角色完整清单、失败恢复、游戏日界线与多个已保存角色轮转。最终整日成功需要七项业务均有游戏状态证据；领取奖励必须另行实现和验收。本轮不添加定时启动。
