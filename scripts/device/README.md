# 设备构建与调试

本目录负责构建、发布、运行、采集和设备诊断，不负责标注制作或离线能力评分。

| 文件 | 职责 |
|---|---|
| `build.py` | 从仓库源码生成 Lua 发布包及哈希清单。 |
| `run-daily.py` | 环境已就绪时，单次构建、发布、运行、等待、采集并验证业务证据。 |
| `start-emulator.py` | 启动或复用指定 MuMu 实例，核验 Android、ADB 与包管理器，就绪后按原范围单次调用 Lua；可显式重启实例一次。 |
| `ts-cli.ps1` | 发布、启动、查询状态和采集；发布前检查空闲状态并校验哈希。 |
| `collect-debug.ps1` | 按轮次归档、校验日志和截图，清理已结束轮次的设备副本。 |
| `inspect-device.py` | 只读截图与 OCR 诊断，不发送任何页面操作。 |
| `dfx_device.py` | 共用设备通信、命令执行与请求实现。 |

使用仓库根目录的 [项目说明](</D:/Agent Repo/my_pocket_automation/README.md>) 查看运行参数和费用边界；具体故障处理见 [DFX 说明](</D:/Agent Repo/my_pocket_automation/docs/DFX.md>)。运行器用于当前主循环，CLI 的默认源码仍是早期登录实验，直接使用时须明确目标源码。

采集先拉到临时文件，通过设备端与本地 SHA256 校验后替换归档。整轮文件已校验后，只有主日志末行明确记录脚本结束，或通过现有授权接口确认触动精灵空闲，才逐个清理设备副本，主日志最后删除。没有结束日志且无法确认空闲时只采集；运行中或校验失败时保留设备文件。仅处理项目命名的日志和截图，不清理 Lua 资源和配置。`run-daily.py` 自动传递临时授权用于空闲检查，采集本身不要求授权。

## 两个原子运行命令

环境已就绪时，单次执行 Lua：

```powershell
python scripts/device/run-daily.py --vm-index 5 --mode run --step daily
```

需要启动或复用模拟器并在就绪后执行一次相同范围的 Lua 时：

```powershell
python scripts/device/start-emulator.py --vm-index 5 --mode run --step daily
# AGENT 已按恢复工作流决定重启实例时，先重启一次再执行相同范围
python scripts/device/start-emulator.py --vm-index 5 --force-restart --mode run --step daily
```

两个命令均要求 `--vm-index`，通过 MuMuManager 精确核对已有实例并读取动态 ADB 端点。`--device` 可省略，指定时必须与该实例当前端点一致；不从 `emulator-*` 或端口猜测实例。`--mumu-dir <目录>` 指定 MuMu 安装目录。两个命令共享实例单次锁，锁仅防止并发调用，不存恢复次数；锁被占用时本次命令退出，不能据此认定 Lua 已结束。

两者默认均为 `--mode observe --step observe`。例如 `python scripts/device/start-emulator.py --vm-index 5` 会在环境就绪后调用一次只读观察；不会自动转换为日常。`start-emulator.py` 直接传递角色、任务、步骤和等待参数，按所选范围调用运行器一次，不先执行 `launch-game`。需要入口专项验收时显式使用 `--mode run --step launch-game`；该结果只证明应用入口就绪，不计日常完成。

`start-emulator.py` 持续读取目标动态 ADB 端口，直到连接为 `device`、Android 完成启动、版本与实例一致且包管理器可用，再启动触动精灵并调用 Lua。ADB 离线时只断开并重连目标端点，不重启共享 ADB 服务。`--timeout 180` 限制单次环境就绪等待，触动精灵接口另限90秒。超时或失败即归档并返回 AGENT，不内部重启模拟器或重跑 Lua。`--force-restart` 只重启所选实例一次，重启后须观察实例关闭或进程变化，再重新读取端点并验收；旧进程在线不能提前证明重启成功。

发布前确认触动精灵接口空闲并校验产物；忙碌或状态未知时不发布。Lua 仍在运行、启动结果未知或无法确认空闲时，两个命令都不从外部强停 Lua、覆盖代码或重发启动；先观察、采集并交 AGENT 判断。游戏内启动、重启及页面操作全部由 Lua 负责，电脑端不按游戏进程是否存活而干预。

## 运行期恢复

恢复顺序、独立故障的次数上限、周二时间窗口和交接条件由 [AGENT 运行期失败工作流](</D:/Agent Repo/my_pocket_automation/AGENTS.md>) 规定。命令只执行一次并返回原始结果；由 AGENT 读证据、决定下一动作并手工记账。Lua 内部已有的有界游戏重启、寻物免费重试与 [拼图方案检验](</D:/Agent Repo/my_pocket_automation/scripts/perception/README.md>) 各自保留。

### 恢复记录模板

按目标在 `debug-runs/recovery/vm-<实例索引>/恢复记录.md` 记录。先核对该目录及原自动恢复历史，承接同目标未解除的故障；不同安装目录复用相同实例索引时须明确区分目标。每次原范围 Lua 验证仍保留独立的 `debug-runs/<轮次>/result.json`、源码包、配置、哈希、日志及画面。记录不含授权，不作为业务进度，也不由脚本自动读取或重置。

```markdown
# VM <实例索引> 恢复记录

- 目标：MuMu 安装目录绝对路径、实例索引
- 原命令与范围：完整参数、角色别名、任务、副本、步骤及等待上限
- 固定版本：源码哈希、bundle 哈希、无授权配置哈希
- 身份资源：逐角色 role.lua 和 selector.lua 哈希
- 历史承接：相关旧记录、未解除故障及累计次数

## 故障 <标识>

- 判断与首个失败：角色、任务、原始 reason 和判断依据
- 关联证据：初次与后续轮次、result.json、日志、画面、源码版本
- 解除所需证据：与该故障对应的业务或环境验收条件
- 累计恢复：Lua <n>/3，VM <n>/3；初次不计；拼图方案单独记录
- 当前状态：未解除 / 已解除；新证据及 AGENT 判断

| 北京时间 | 动作前判断和证据 | 预记动作及累计次数 | 原范围命令和版本核对 | 请求、结果与归档 | 下一步 |
|---|---|---|---|---|---|
| <时间> | <Lua 状态、故障、证据> | <Lua 或 VM，第 n 次；窗口是否适用> | <原命令与哈希一致> | <尚未请求 / 已请求 / 请求未知；结果路径> | <取证 / 继续 / 解除 / 交接> |
```

动作前预记，确定未发请求时才注明依据并撤销该次；请求结果未知保守保留次数并先取证。实例重启附带的 Lua 验证仅记一次 VM 恢复。换原因文案、命令、会话或进程不清零，只有 AGENT 根据新证据确认旧故障解除，才记录结论并为后续独立故障建立预算。拼图修复允许更换版本，每次仍关联还原、自查、回归与设备检验记录。首次执行、窗口内动作及窗口结束后的累计次数都如实保留。

## 已保存角色轮转

已有任务使用 `python scripts/device/run-daily.py --vm-index <索引> --task zhuagui --mode run --step complete --account <别名>` 继续。Lua 从游戏页面恢复未完成任务；同日同角色已核验完成的任务可以复用设备上的完成账本。本次已核验状态直接复用。

`--step daily --tasks shimen,zhuagui,dungeon --select-accounts <别名1> <别名2>` 配置本轮的多个角色和任务范围。完整已登录名单仍由 `--accounts <仓库外配置.json>` 提供；Lua 核对完整名单后只执行选中角色，按名单顺序运行。完整日常须逐号推进：同一角色按师门、抓鬼、两个副本、开葫芦完成并验收后，才能切换下一号；不要将五号拆成先全部师门、再全部抓鬼的阶段。`--account <别名>` 选择单角色；省略角色选择则遍历配置中的全部角色。身份和进度按角色隔离。

`python scripts/device/run-daily.py --vm-index <索引> --mode run --step daily --tasks zhuagui,dungeon --max-seconds 10800` 遍历外部配置的全部已登录角色，核对选择页名单与每次进入后的身份。遇到未配置卡片或名单不完整时 Lua 停止当前运行，返回证据供 AGENT 按上述工作流判断，不遗漏新角色。

`~/.my_pocket_automation/daily-accounts.json` 保存稳定别名与逐角色策略；身份、选择特征由 `calibrate-role.py` 保存到同一外部配置目录。别名不得重新绑定其他角色，运行期状态按别名隔离，重启后从游戏重建未完成任务。新角色需要先从已登录选择页和主页校准身份资源；工具不输入账号密码。

每个角色用 `claim_dungeon_rewards` 配置副本现场领奖政策，默认禁止领取；允许领取的角色在通关并核对领奖按钮后发送一次破解封印请求。请求先在内存中标记，未知结果不重复点击。宝库开葫芦由独立的 `rewards` 收尾模块处理。

`--account <已配置别名>` 用于有界的单角色恢复；与 `--step daily` 组合时，核对全名单后仅运行指定角色，汇总范围为 `selected_roles`，不会报告全部角色完成。副本接管已有战斗只被动等待；抓鬼可推进已记录任务的免费对话、寻物和重试。身份未核对时不新接任务，不记录抓鬼完成；返回待接取页面后先核对主页身份。

每个副本默认最多等待60分钟，覆盖连续多场战斗；运行器默认完整流程等待10800秒，`complete/advance` 等待3900秒，`--max-seconds` 可明确设置电脑端上限。超时保留已启动记录，先检查现场再恢复，不重新开启副本。

`--dungeons wuji` 将副本范围设为乌鸡国。师门和抓鬼持续推进至明确完成卡片，副本持续至通关状态；完成判断不读取任务数量，不设置费用预算或数字任务目标。寻物识别失败最多免费重试3次，先保存错误现场；其他页面错误不触发该重试。

运行器默认开启聚合 Profile。主日志仅保留角色与任务起止、验收、恢复重试和结果；`_error.log` 按需保存错误与失败截图路径。正常过程、完成卡片和葫芦空列表不归档；寻物在识别所需的同一轮滚动中逐页缓存原图、识别并复核作答，不先预采再回滚；拼图保存操作前原图。交付成功后清理临时素材，失败及待验收时保留，完整题目自动去重拼接，缺页标记不完整。原图与拼接图路径见 `result.json.recognition_materials`，不能将缺页或高度达标直接当作完整真值。领奖收据及显式采集原图保留。排查时用 `--verbose-logs` 开启 DEBUG，用 `--routine-screenshots` 开启过程截图；二者不关闭识别素材采集。


`selected_complete` 表示本轮所选范围内的角色都完成所选任务；指定单角色时不能据此称作全部角色完成。`daily_complete` 只有全部配置角色的师门、抓鬼、副本、葫芦收尾四类都完成时才为真。默认任务顺序为 `shimen,zhuagui,dungeon,rewards`，显式选择也按该顺序执行。师门仅覆盖已采集页面与已确认题型，不能把部分任务当作全部日常完成。

葫芦调测使用 `--task rewards --mode run --step complete --account <别名> --rewards-debug-after-shimen`：Lua 核对该角色师门完成卡片后，自动开光宝库任务、副本葫芦并丢光特殊葫芦。`enter/browse` 只看列表或详情，可用 `--rewards-inspect-category task|dungeon|special` 采集；`advance` 只执行一次业务动作。调测不记开启数量，也不会报告 `daily_complete`。



师门已有任务使用 `python scripts/device/run-daily.py --vm-index <索引> --task shimen --mode run --step advance --account <别名>` 单步推进；`--step complete` 在交付与身份核对后继续领取下一项，最终通过师门已完成卡片验收。设备 Lua 负责全部操作；寻物首次尝试后最多免费重试3次，拼图先匹配旧特征中的唯一题型，不能识别或不能完成则保存现场停止。启动时仅复用同日、同身份的完成布尔状态，不读取旧日期进度或重试记录。免费重试分支和未见题型尚未全部设备验证；未知页面有界等待后仍会停止。

## 每日完成账本与新增角色

Lua 在设备 `res/daily_completion.tsv` 原子写入业务日、稳定别名、主页身份资源哈希、任务名与 `true`。只允许师门、抓鬼、乌鸡国、车迟斗法、开葫芦的完成状态；不保存任务内部进度或重试次数。两个副本分别记录，避免只完成一个就跳过另一个。日期或身份资源变化后不能复用；未核验身份不读取、不写入。领奖请求、未领奖通关和调测清空不记完成。完成新的日常任务会使旧的开葫芦状态失效。账本用于断点恢复，运行日志和截图仍独立归档。

新增已登录角色：先校准选择页姓名特征，然后用 `--mode run --step select-role --account <别名>` 由 Lua 切换并采集主页；此入口只供身份校准，不能报告日常完成。人工查看或 AGENT 核对原图后用 `calibrate-role.py --kind role` 保存主页姓名特征，再运行正式任务。角色选择支持有界双向滚动，正式运行始终核对完整名单与所选角色身份。

选择页更新后若口袋主页仍保留旧角色，Lua 可重启游戏并从已登录入口重新进入一次，等待入口最多180秒，然后重新核对主页身份；无法确认时停止。已核验的遮罩设置页在返回失败后也使用此入口恢复。重启不接管账号认证，不将选择页的“当前”标记当作主页身份或任务完成证明。
