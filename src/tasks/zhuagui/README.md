# 抓鬼

已实测野鬼、马面、牛头、僵尸、蛇胆酒、骷髅怪、书画、蜡烛寻物及战斗。识别用例按任务、题目和场景保存，见 [用例说明](</D:/Agent Repo/my_pocket_automation/testdata/README.md>)；黄纸、香炉、金色短剑等新增外观已获用户确认并通过方向用例，尚未在设备选择中验证。方向资源离线预生成，不增加运行时变换策略。设备能力边界和当前回归结果见 [当日实测报告](../../../docs/REGRESSION_20261011.md)。

兵器寻物未命中或超时，仅在明确的免费重试页自动续试；首次之外最多重试3次，计数随角色当天的已接任务持久化，下一项接取才清零。不重新接任务、不追加精力；重试题目可能轮换，新的非兵器识别失败仍保存现场并停止。重试按钮点击前先保存计数，运行中断也不重置预算。显式只采集轮次不属于自动完成重试。

## 流程与资源

`task.lua` 管理接取、前往、对话、寻物、战斗等待、完成确认和继续；`pages.lua` 判断当前页面；`find.lua` 先识别题目类别，再遍历该类别图标，在有限滚动范围内寻找；`counter.lua` 读取次数。识别资源全部放在本任务的 `assets/`。

同一角色连续完成任务时留在钟馗对话页接下一项，不每项回主页。每次接取仍核对未进行任务、3精力费用、次数与进度一致，并先保存预算预留；只有首次进入或恢复后身份未验证时才回主页核对身份。

旧版寻物数据已完整继承：13 组题目特征、113 组物品特征，包含旧版未命名兜底；另保留 7 类拼图的 28 组图块及原始槽位。`assets/legacy.lua` 可由 `scripts/perception/import-zhuagui-legacy.py` 重现，来源和许可见 `参考代码/`。未命名兜底不用于未知题目乱选；拼图槽位尚未在新版界面验证，不执行放置。

寻物按题目查询离线生成的 `catalog.lua`，每页共用一帧做多点找色，找到后释放画面并重新验证再点击。旋转、镜像及冗余特征去除由开发工具完成，运行时不变换资源。已校准类别不叠加旧版兜底；未校准类别仍保留旧识别入口，但不声称已适配新版。

**页面的 N/25 不等于完成 N 次。** 新任务接取后次数就增加；只有返回未进行任务的页面、次数与本地记录一致，才能记为完成。次数读取排除分隔斜杠并保留完整数字宽度；多种已审核字形并存，不靠降低阈值接受未知数字。无法可靠读取时暂停。

## 运行与恢复

```powershell
# 默认观察；不接任务
python scripts/device/run-daily.py --device emulator-5562 --task zhuagui --mode observe
# 继续已有任务，完成一项就停，不接下一项
python scripts/device/run-daily.py --device emulator-5562 --task zhuagui --mode run --step advance --zhuagui-budget 75
# 在授权的日内预算内继续，遇到未适配画面停止
python scripts/device/run-daily.py --device emulator-5562 --task zhuagui --mode run --step complete --zhuagui-budget 75
```

预算默认 0，只接受 0–75 中 3 的倍数。接取前核对角色，并先持久化预留 3 精力；已有任务只续跑，不重复领取。设备进度分别保存 `attempts`（已预留接取）、`completed_count`（已验证完成）、`reserved_energy`（费用上限占用），失败重启不清零。预留不代表已扣费。

主页任务入口在有未完成任务时可能直接打开 NPC 对话。恢复按画面和所属记录判断，不强求先出现任务列表。战斗只等待；找物品点击后必须确认找物品页面退出，未成功不重复点。找物品每页保存截图，滚动保留足够重叠，避免图标始终只露半边。

识别断点可用 `--step browse` 只采集候选，不选物品；再执行 `python scripts/perception/prepare-zhuagui-breakpoint.py --run-id <运行编号>` 生成带页码的截图总览和原图索引。用户标注后从对应原图校准，复测点击结果。

批量只采集使用 `--step browse --browse-rounds 20 --zhuagui-budget 0`：只重试已有任务和滚动，每题采集七页，不调用寻物选择器。采集后用 `scripts/perception/import_frame.py` 按题目、轮次导入脱敏原图，先保存为待审核，再通过 `annotate.py` 应用明确批准的答案。重复题目不增加覆盖数；不完整页和到时负样本保留，但不能冒充有效题目。运行次数和测试通过都不能替代缺项清单。

抓鬼模块不领取或开启葫芦。900×1600布局单角色25项已实测完成；跨日恢复和完整多角色任务轮转仍需独立验收。

## 审核特征

用户批准的答案实例生成新版多点颜色特征，覆盖书籍、书画、兵器、黄金和泛化酒。离线生成方向特征并同步计算点击偏移，增强用例验证各方向和位置。具名酒不会借用泛化酒集合；已审核的蛇胆酒、野鬼、马面、牛头、黄纸、僵尸另有内部平滑区域特征，其余具名酒和新版拼图仍需独立适配。校准来源和哈希随资源保存；单答案与明确负例的增强用例进入生产回归，拟合通过不等于所有题型设备验收通过。

到达25项后，游戏会关闭详情页，把变灰的抓鬼卡片移到列表底部。脚本只在任务列表内有界滚动，联合识别抓鬼名称与同一卡片的“已完成”标记；账本须匹配最后一次待确认记录，否则拒绝补记。不会把卡片消失视为完成。

采集入口可以从已有任务的免费对话恢复，但要求该角色存在running账本；不处理付费接取页，也不选择候选。重试后的游戏提示遮挡标题时，等待已知页面恢复，超时停止。香炉题干保留原文，按用户批准映射到“香”采集类别；未审核的答案不能用于校准。
