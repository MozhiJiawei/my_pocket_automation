# 副本机制

新版乌鸡国、车迟斗法由同一副本控制器调度；专用标题、卡片和完成特征跟随各自目录，共用列表、战斗、返回资源放在副本的 `assets/`。

设备端循环执行“识别页面 → 选择动作 → 再次定位并点击 → 验证新页面”。识别使用当前实测截图提取的多点颜色特征，限制屏幕尺寸和区域；不是单纯重放坐标。点击位置相对识别锚点计算。电脑 OCR 只辅助采集和分析，没有参与设备实时业务决策。

## 实测路径

1. 从主页进入副本；若恢复已有完成或封印页，先核对状态，再安全返回列表。公共列表遍历先查完成标记：乌鸡国标题与“进入宝库”同时出现，或车迟斗法卡片有绿色勾，即普通副本葫芦已领取，直接跳过。否则根据卡片和标题确认目标，可有界双向滑动查找。
2. 进入五关总览。确认目标标题和“开启”，在运行期账本中标记请求，再点击一次。
3. “开启”后游戏自动完成副本。Lua 只观察最终完成状态、中断及超时，不逐关点击继续或下一关，也不循环操作倍速。进行中总览短暂出现属于正常转场；停留30秒未继续时保存中断现场并暂停。
4. 最后出现“任务完成，发现被封印的……葫芦”。记录通关证据，通过左下返回离开奖励页，验证五关“已完成”。
5. 未领取封印奖励会继续占用当前副本，切换时游戏要求放弃。仅在当前角色及前副本通关证据均明确时确认；战斗中或五关未完成时不切换。正常执行乌鸡五场，再车迟五场。
6. 两个副本均完成后回主页。

Lua 核验列表领取标记后才写入完成账本，有效记录可复用；通关未领奖结果仅在本次运行内保留。缺少有效记录时从游戏页面恢复，账本规则见 [每日完成账本与新增角色](</D:/Agent Repo/my_pocket_automation/scripts/device/README.md>)。

恢复未完成副本时，以明确通关页面验收，并按该角色领奖政策处理；不要求重打已经完成的副本。战斗或加载页可直接等待至目标通关页面。身份或日期未核对时不得验收完成或领奖。

启动时若停在已有任务的“前往迎敌”页，只恢复一次当前战斗；按钮被触动精灵启动提示遮挡时先有界等待。开始后回到只读观察。通关总览的免费领奖入口点击后仍停在原总览时，经主页重新进入一次；未知页面停止，不重复领奖请求。领奖核验100精力确认框，成功弹窗安全关闭或自动消失后，以副本列表的领取标记验收，不依靠短暂弹窗恢复完成记录。任务入口的“2/7”可供汇总查看，不代替具体副本的完成标记，也不要求重新打开已核验副本。

## 护栏与反馈

默认不领取副本奖励；MS墨汁005的策略为禁止领取。其他角色只有外部配置明确允许、身份与领奖按钮核对通过时才可请求领取，未知结果不得重复请求。界面中的原生奖励弹窗可以出现，脚本不另加信息弹框或 toast。

乌鸡国只确认消耗100精力领取副本葫芦，葫芦留到任务完成后在口袋宝库统一开启。“乌鸡国宝库”不进入、不解锁、不购买；领取成功弹窗使用“点击空白区域关闭”，不点击“乌鸡国宝库”按钮。

日志与截图遵循 [DFX](</D:/Agent Repo/my_pocket_automation/docs/DFX.md>)：默认不保存常规动作、战斗等待及成功页面截图；失败现场、领奖收据和显式采集留证，已有失败证据不重复截图。未知奖励立即暂停，其他未知页面持续三十秒后暂停；每个五场副本战斗等待最多六十分钟。暂停后不重新开启副本，外部恢复按 [设备运行期恢复](</D:/Agent Repo/my_pocket_automation/scripts/device/README.md>) 执行。

运行器的 `observe` 是只读；`daily` 串联两个副本。开发步骤 `enter/start/advance/finish` 用于消耗机会前逐步验证，不是任意页面通用点击命令。同一次运行的请求未验证时拒绝重复开启；重启后尚未完成的副本以游戏当前页面判断。进程退出不等于通关，必须看到完成提示或五关完成证据。

目前只验证了一个角色、900×1600 口袋界面及 1600×900 入口。更换分辨率、主题、角色或游戏更新后的页面校准仅用于显式开发维护，运行故障按上述策略处理。有限的真实机会用于确认新状态，已保存的脱敏截图用于离线回归。
