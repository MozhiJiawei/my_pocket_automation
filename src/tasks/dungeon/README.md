# 副本机制

新版乌鸡国、车迟斗法由同一副本控制器调度；专用标题、卡片和完成特征跟随各自目录，共用列表、战斗、返回资源放在副本的 `assets/`。

设备端循环执行“识别页面 → 选择动作 → 再次定位并点击 → 验证新页面”。识别使用当前实测截图提取的多点颜色特征，限制屏幕尺寸和区域；不是单纯重放坐标。点击位置相对识别锚点计算。电脑 OCR 只辅助采集和分析，没有参与设备实时业务决策。

## 实测路径

1. 从主页进入副本；若恢复已有完成或封印页，先核对状态，再安全返回列表。根据卡片和标题确认目标，可有界双向滑动查找；卡片支持选中与未选中字形。
2. 进入五关总览。确认目标标题和“开启”，先写当天运行记录，再点击一次。
3. “开启”直接开始战斗；战斗自动进行，胜利后的三秒倒计时自动进入下一关。识别到一倍速时切为二倍速，其余时间等待，不连续点击“下一关”。
4. 最后出现“任务完成，发现被封印的……葫芦”。记录通关证据，通过左下返回离开奖励页，验证五关“已完成”。
5. 未领取封印奖励会继续占用当前副本，切换时游戏要求放弃。仅在当前角色及前副本通关证据均明确时确认；战斗中或五关未完成时不切换。正常执行乌鸡五场，再车迟五场。
6. 两个副本均完成后回主页，保留完成记录，下一次运行跳过。

恢复时看见的未归属完成页只记 `observed`，供安全离开已完成副本使用，不算今日完成，也不阻止从明确“开启”页开始今日任务。只有本日已记录启动的任务，才可在完整通关证据后记 `done`；未知日期不能靠画面猜测。

## 护栏与反馈

默认不领取副本奖励；MS墨汁005的策略为禁止领取、预算0。其他角色只有外部配置明确允许、身份与100精力按钮核对通过、预算足够时才可请求领取，未知结果不得重复请求。界面中的原生奖励弹窗可以出现，脚本不另加信息弹框或 toast。

每次动作前后截图，状态变化写日志，战斗等待每三十秒留证据。未知奖励立即暂停，其他未知页面持续三十秒后暂停；每个五场副本战斗等待最多六十分钟。暂停不重开副本，应先读日志、截图，再校准和恢复。

运行器的 `observe` 是只读；`daily` 串联两个副本。开发步骤 `enter/start/advance/finish` 用于消耗机会前逐步验证，不是任意页面通用点击命令。记录先于启动；已有记录时拒绝再次开启。进程退出不等于通关，必须看到完成提示或五关完成证据。

目前只验证了一个角色、900×1600 口袋界面及 1600×900 入口。更换分辨率、主题、角色或游戏更新后，先观察再校准。有限的真实机会用于确认新状态，已保存的脱敏截图用于离线回归。
